## Finding 1 — the Playwright Python image has no `playwright` Python package

`mcr.microsoft.com/playwright/python:v1.64.1-noble` contains the browsers (`/ms-playwright`) and their system
libraries only. Its build installs the wheel into a throwaway venv (`/ms-playwright-agent/venv`), runs
`playwright install --with-deps`, then `rm -rf /ms-playwright-agent`. Every first run therefore failed with
`ModuleNotFoundError: No module named 'playwright'` in all four modes. Fix (`runner/Dockerfile`):
`pip install --break-system-packages playwright==<version from PW_TAG>` at build time. The build uses the host's
network; the runner still has none at run time.

## Step 4 — sandbox matrix

Base limits for every try: `--network dp-net --user pwuser --read-only --tmpfs /tmp:rw,size=256m --cap-drop ALL
--security-opt no-new-privileges --memory 1g --memory-swap 1g --pids-limit 256 --shm-size 512m --cpus 1 --rm`,
no `-e`/`--env-file`. Order tried: A → B → B3 → C, stop at the first that works; D is diagnostic only.

| Try | Extra docker flags | Chromium | Result | Why |
|---|---|---|---|---|
| A | none (Docker default seccomp) | sandbox on | **FAIL** | `No usable sandbox!` — default seccomp refuses `clone`/`unshare` of a user namespace without `CAP_SYS_ADMIN`; the setuid helper is ruled out by `no-new-privileges` |
| B | `--security-opt seccomp=seccomp/playwright-v1.64.1.json` | sandbox on | **FAIL** | `Check failed: sys_chroot("/proc/self/fdinfo/") == 0`, zygote exits. Playwright's profile allows `clone`/`unshare`/`setns` unconditionally but keeps Docker's rule that allows `chroot` only `includes.caps: [CAP_SYS_CHROOT]`; with `--cap-drop ALL` that rule never applies |
| **B3** | `--security-opt seccomp=seccomp/playwright-v1.64.1-chroot.json` | sandbox on | **OK — chosen** | only difference from B: the cap-gated `chroot` rule replaced by an unconditional allow (verified by diff). Caps stay `ALL` dropped |
| D | `--security-opt seccomp=unconfined` | sandbox on | OK (diagnostic) | confirms seccomp is the only blocker; unprivileged user namespaces work on this kernel |
| C | none | `--no-sandbox` | OK (not needed) | fallback only |
| (B2) | B + `--cap-add SYS_CHROOT` | sandbox on | OK (one-off test, not in `run.sh`) | works too, but adds a capability; B3 preferred |

Why B3's loosening is small: seccomp only decides whether the syscall reaches the kernel. Outside its own user
namespace `pwuser` has no `CAP_SYS_CHROOT`, so the kernel still refuses `chroot` there. It only succeeds inside
the user namespace Chromium creates — which B already allows. The real loosening (inherited from Playwright's
profile) is unprivileged `clone`/`unshare` of namespaces.

**Evidence the sandbox is on (replaces `chrome://sandbox`).** Headless shell does not serve `chrome://sandbox`
(`net::ERR_INVALID_URL`), so `visit.py --launch-only` now opens a page and compares `/proc/<pid>/ns/{user,pid,net}`
of every Chromium process with its own. `attempt` treats sandbox-on as OK only if at least one process is in new
namespaces.

| Mode | Chromium processes in new user+pid+net ns |
|---|---|
| B3 | 3 / 7 (`zygote`, `renderer`) |
| D | 3 / 7 |
| C | 0 / 6 |

## Re-running on Windows (Git Bash + Docker Desktop)

```bash
# Git Bash would rewrite "/tmp:rw,..." and other absolute-looking args into Windows paths
export MSYS_NO_PATHCONV=1
# python3 on Windows is often the Microsoft Store stub; give run.sh a shim to the real python
mkdir -p ~/bin && printf '#!/bin/sh\nexec python "$@"\n' > ~/bin/python3 && chmod +x ~/bin/python3
export PATH=~/bin:$PATH
PW_TAG=v1.64.1-noble ./run.sh          # setup + sandbox matrix + visits
./run.sh isolation
./run.sh measure
KS="1 2 4 6 8" ./run.sh parallel
./run.sh clean
```

Setting `PW_TAG` skips the MCR tag lookup and keeps the committed seccomp profiles in use.

## Notes for deploying B3 on a Linux VM

B3 needs **unprivileged user namespaces** on the VM's kernel (Chromium's namespace sandbox creates them as
`pwuser`). Check before relying on it:

```bash
sysctl kernel.unprivileged_userns_clone              # Debian/older Ubuntu kernels: must be 1 (absent elsewhere = fine)
sysctl kernel.apparmor_restrict_unprivileged_userns  # Ubuntu 23.10+: 1 blocks the sandbox
sysctl user.max_user_namespaces                      # must be > 0
```

On this WSL2 kernel the first two do not exist and `user.max_user_namespaces=31256`. If AppArmor restricts
userns (Ubuntu 23.10+/24.04 default), B3 fails like A; the options are an AppArmor profile for Docker containers
that permits `userns`, or setting the sysctl to 0 on the VM (host-wide; decide deliberately). Mode C stays the
fallback. Re-run `./run.sh sandbox` on the VM: the matrix and the namespace evidence show which mode is real
there. The seccomp profile path must be valid on the VM's Docker host (`--security-opt seccomp=<path>` is read by
the docker CLI).

## Known problems / limits

1. Script-target discovery is a static regex over inline scripts, `on*` attributes and same-host external
   scripts (`fetch`, `xhr.open`, `sendBeacon`, `$.post/get/ajax`, `axios`) plus any absolute URL literal.
   Obfuscated/constructed URLs will be missed; runtime instrumentation only sees calls that happen without
   interaction (by design we never click).
2. `/step2` redirects 1.5 s after load so it can be screenshotted. An immediate `location.replace` in an inline
   script would leave no screenshot of that page; the redirect itself is still recorded.
3. The download request does not show up in `network` (Chromium hands it to the download manager); it is in `downloads`.
4. Screenshots travel inside the JSON (`jpeg_b64`) because the runner has no writable mount; `check.py` extracts them.
5. Measurements are from a laptop under Docker Desktop/WSL2, not the target VM; the parallel test pins CPUs but
   does not cap total memory.
6. The B3 profile is tied to Playwright v1.64.1's upstream profile; regenerate (and re-run the matrix) when the
   image tag changes.
